# 同名文件上传改为提示复用/新建

> 2026-10-14 c132 端侧验证发现：向笔记本上传**同名但内容不同**的文件会静默创建第二行
> 来源（内容哈希去重按设计只匹配完全相同字节）——用户视角即「重复上传没有任何提示」，
> 来源列表与搜索结果出现同内容观感的重复条目。本 change 把同名命中纳入既有去重
> 确认流：409（kind='filename'）→ 复用（跳过上传返回既有）/ 新建（独立副本）。

## Why

- 内容去重（r298 门控）与 UI 确认弹窗已完备；同名不同内容是唯一漏网的静默重复路径。
- 用户预期：上传「已存在」的文件应被询问，而不是悄悄多一份。

## What Changes

- 上传端点：门控开启时，内容未命中但**笔记本内存在同名可见来源** → 默认动作 409
  SOURCE_DEDUP_HIT（details 带 `kind:'filename'`、既有 id 与文件名）；`reuse` 跳过上传
  返回既有来源；`create_new` 照常创建。门控关闭时行为不变。
- 前端：复用既有去重弹窗，按 kind 区分提示文案（内容相同 / 同名不同内容）。
- specs：`source-ingestion-upload-and-url` 新增 r490。

## BREAKING

无（新增一种 409 触发情形，语义与既有 SOURCE_DEDUP_HIT 一致）。
