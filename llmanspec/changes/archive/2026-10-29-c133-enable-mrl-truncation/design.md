# MRL 截断启用 — 设计权衡

## D1. 截断落点：网关参数优先，客户端切片兜底

| 路径                | 机制                                                          | 取舍                                                                |
| ------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------- |
| ① 网关侧（首选）    | embed 请求带 `providerOptions: { openai: { dimensions: N } }` | 网关截断 + 归一化一步到位；真机实测可用（tufa:50233）；依赖网关能力 |
| ② server 侧（兜底） | engine 收到全维向量后 `vec.slice(0, N)` + L2 再归一化         | 不依赖网关；实现直白；每向量多传 2/3 流量（个人 KB 规模无感）       |

运行时探测：首次 embed 时发 1 次带 `dimensions` 的探针请求，成功即固定走 ①，失败（网关
忽略或报错）降级 ② 并在 logger 记录探测结论。**不做**每请求探测（省一次 RTT 与分支抖动）。

## D2. 再归一化是硬约束，不是优化

归一化向量的 cosine 可退化点积；截断后模长 ≠ 1，不重归一化则所有相似度得分失真且**静默**
（不报错、排序悄悄变差）。因此：

- 路径 ② 内联 L2 归一化，无开关；
- 路径 ① 归一化由网关负责，engine 入库前**校验模长**（容差 1e-3），越界即 warn 日志
  （网关若违约可见，不阻断——避免网络抖动误伤）；
- issue #7 验收「MRL 截断开启时强制 renormalize」由以上两点承接，配锁测。

## D3. eval 基准：scoped 回归，不是复活 c73 全量 Harness

c73 移除 Eval Benchmark Harness 的理由是「无 UI/CI/CLI 消费者」。本 change 提供明确消费者：
MRL 启用决策的 go/no-go。因此评估面刻意收窄：

- **语料**：固定 fixture（`tests/rag/mrl-eval/corpus`，数十文档），不接真实用户库——
  可复现、可进 CI；
- **判据**：已知查询对 × recall@k / nDCG@10，768 维基线 vs 512/256 截断，报告落盘 JSON+MD；
- **门槛**：256 维 recall@10 相对衰减 > 5% 即 no-go（写死在 eval runner 的退出码里）；
- **边界**：不做并发/延迟基准（BENCHMARK.md 已有吞吐数字），不做检索策略对比。

## D4. 配置面与迁移

- config 新增语义：embedding 目标维度（可选；null/缺省 = 不截断，**默认关闭**）。数值
  合法域 = 所选模型 `mrlDims` 声明的成员（消费 c130/r474 的声明，杜绝配置写 300 这种
  模型不支持的维度）；非法值启动即拒（configuration-governance 既有校验流水线）。
- 开关变更 → dims 变化 → 走既有 vec_chunks 维度守卫（r478：boot 警告 + 重建指引、
  runtime EMBEDDING_DIM_MISMATCH）与 c131 重建入口。**本 change 不新增迁移路径**。

## D5. 回滚

默认关闭 = 无行为变化；启用后回滚 = 关开关 + 重建索引（既有入口）。eval 报告保留在
tests 目录供后续复检。
