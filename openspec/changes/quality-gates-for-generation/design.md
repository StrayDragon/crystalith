## 背景

当生成类型越来越多之后，系统不能只关注“能不能生成”，还需要回答“这个结果是否达到最小可用标准”。质量门的价值不是把产品变成审批系统，而是建立最小可复用的质量信号与告警语义。

## 已确定决策

### D1：质量门是运行时信号，不是重型审批流程
- 质量门先提供通过 / 警告 / 阻断这类最小状态。
- 它服务生成结果治理，不替代正式审阅工作流。

### D2：质量门必须可跨类型复用
- 同一套质量门能力要能服务多个生成类型。
- 不为某个单一输出单独发明一套规则模型。

### D3：质量门需要返回结构化原因
- 质量门不能只有布尔值。
- 至少需要返回触发原因、涉及维度和建议动作。

### D4：v1 不覆盖所有质量策略
- 本次先固定最小可复用质量信号与接入位置。
- 更复杂的评分模型、回归体系联动和自动修复后置。

## 已确定的具体定义

### 质量门与审阅流程的边界

- **质量门**：自动、运行时、面向结果整体、输出结构化信号
- **审阅流程**（evidence-review-workflow）：手动、面向具体证据/引用、状态由用户显式推进
- **连接点**：质量门的"警告"可以作为建议用户审阅的触发提示，但不强制

流程顺序：
```
生成完成 → [自动] 质量门检查 → 通过/警告/阻断
                                    ↓
                              结果可见但带标记
                                    ↓
                         [手动] 用户发起 evidence review
```

### 质量门分级：告警 vs 阻断

| 质量门 | 级别 | 理由 |
|--------|------|------|
| Schema 合规性检查（结果结构是否完整） | **阻断** | 不合规的结构无法正确渲染 |
| Citation 覆盖率（引用率低于阈值） | **警告** | 低引用不意味无法使用 |
| 来源充分性（可用来源少于预期） | **警告** | 用户可能知情且接受 |
| 关键字段缺失（标题/摘要为空） | **阻断** | 缺少关键信息的结果不可用 |
| 长度偏差（过长或过短于目标） | **警告** | 用户可通过 refinement 调整 |

### D3 补充：质量门结构化返回格式

质量门返回至少包含：
- `gate_id`: 质量门标识
- `status`: `pass` | `warn` | `block`
- `dimension`: 涉及维度（如 `schema_compliance`, `citation_coverage`）
- `reason`: 触发原因描述
- `suggested_action`: 建议动作（如"检查引用完整性"、"补充来源后重试"）

### 后置项说明

- D4 中的"更复杂的评分模型、回归体系联动和自动修复"后置条件：**待用户反馈后评估**，属于"确认需要但延迟"类型

## 非目标

- 不在本 change 中构建完整审阅审批系统。
- 不为单一结果类型定制专属质量框架。
- 不在本 change 中承诺自动修复所有质量问题。
