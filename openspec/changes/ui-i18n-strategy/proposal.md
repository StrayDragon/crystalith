## Why

- 当前仓库在用户可见层面存在中英文混用：前端 UI 文案以中文为主，而部分文档与对外入口为英文。对外发布与生态扩展时，这会造成体验割裂（同一功能不同语言）、降低可读性与可维护性（字符串散落、难以统一更新）。

## What Changes

- 明确产品语言策略并工程化落地：
  - 定义 UI/Docs 的目标语言与默认语言（例如：默认中文 + 可选英文，或统一英文）。
  - 约定字符串来源与组织方式（集中管理、避免散落硬编码）。
  - （如选择多语言）提供最小 i18n 基础设施与语言切换入口（本地存储偏好、跟随系统等）。
- 以 Workspace 关键路径为首批覆盖范围（Sources/Chat/Studio/诊断/导出等），逐步收敛存量文案。

## Capabilities

### New Capabilities

- （无）

### Modified Capabilities

- `workspace-ui-core`: Workspace 顶层体验需要明确语言一致性与可访问的语言策略（默认语言、切换/持久化行为与覆盖范围）。

## Impact

- Frontend: 需要引入/实现字符串管理与（可选）i18n 方案，并对现有组件进行逐步替换。
- Docs: 需要明确文档语言策略并与 UI 保持一致（至少在入口与关键页面保持统一）。
- Testing: 可能需要为关键 UI 文案或语言切换增加基础测试/快照策略（避免回归）。
