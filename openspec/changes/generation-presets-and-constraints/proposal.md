## Why

即使同一种生成类型，用户真正要的结果也常常差很多：有的要简短结论，有的要深入分析；有的面向老板，有的面向新人；有的要求强证据约束，有的更偏启发与发散。如果所有生成都只能靠一次自由输入或隐含默认值来控制，结果往往会出现：

- 用户很难稳定复现“上一次那个比较好的结果”
- 系统知道很多可调参数，但产品没有把它们变成易用控制项
- 不同生成类型的控制需求差异很大，却被迫共用一套粗粒度配置

因此，这个 proposal 聚焦于 **generation presets and constraints**：为不同生成类型提供明确、可理解、可复用的预设与约束体系。

## What Changes

- 为生成类型引入 preset 与 constraint 概念，而不是只依赖自由 prompt 输入
- 支持按类型定义控制项，例如：深度、长度、语气、受众、结构偏好、证据严格度
- 让系统可以提供少量高价值预设，而不是暴露一大堆零散参数
- 支持不同生成类型拥有不同控制集合，而不要求所有类型共享同一套选项

## Before / After

### 实现前
- 生成控制主要依赖自然语言补充说明或隐含默认值
- 用户难以重复获得风格一致、约束一致的结果
- 不同类型的控制需求无法被清晰表达

### 实现后
- 每个生成类型都有更清楚的控制面板和预设选项
- 用户可以更稳定地生成“我想要的那种结果”
- Crystalith 不只是“会生成”，而是“会按意图生成”

## 优点

- 提升生成结果的可控性和复现性
- 让复杂能力以更易懂的产品形式暴露出来
- 非常适合与模板、工作流和后续类型优化协同

## 风险与代价

- 控制项设计过多会让右侧面板变复杂
- 若预设命名不清，反而会让用户更困惑
- 不同类型之间很难完全统一一套约束模型

## Capabilities

### New Capabilities
- `generation-presets-and-constraints`: 提供按生成类型组织的预设、约束与控制项体系

### Modified Capabilities
- `generation-core`: 需要承载各类型的 preset / constraint 装配与执行语义
- `chat-prompt-presets`: 需要与生成类型预设体系对齐，而不再只是聊天提示预设
- `workspace-ui-panels`: 需要在右侧生成面板中按类型展示控制项
- `workspace-api-contract`: 需要暴露 preset、constraint 和类型配置接口

## Impact

- Backend
  - 新增预设模型、约束装配与参数校验逻辑
- Frontend
  - 新增按类型组织的控制项、预设选择和解释 UI
- Product
  - 右侧生成按钮从“发起生成”升级为“发起可控生成”
