## Context
右侧输出区域需要从“单结果 + 队列切换”升级为“输出中心 + 多结果卡片”，并与左侧来源/引用形成更紧密的交互闭环。

## Goals / Non-Goals
- Goals:
  - 输出中心支持多卡片并存、队列状态提示、卡片操作与空状态引导。
  - 来源/引用提供更明确的状态反馈与跨栏联动。
  - 三栏布局具备清晰视觉层次与独立滚动体验。
- Non-Goals:
  - 不调整后端 API 协议与数据模型。
  - 不引入新的第三方 UI 框架。

## Decisions
- 采用前端 TaskQueue 状态管理：每次触发提炼时创建占位卡片，队列状态从 queued -> running -> done/error。
- 通过弹出式配置面板控制自动提炼与后台队列开关；开关状态保存在前端本地状态。
- 引用悬停高亮通过在消息记录中附加引用 chunkId 列表实现。
- “对话后自动触发提炼”保持关闭，仅允许用户点击提炼卡片触发任务。
- “生成对比分析”使用独立模板 prompt（compare-analysis）。

## Risks / Trade-offs
- “重试”图标暂仅表现状态提示，如需真实重试需后端支持上传/重试 API。
- 多卡片列表在长时间使用后可能需要分页或归档策略（暂不实现）。

## Migration Plan
- 前端静态改造，无数据迁移。
