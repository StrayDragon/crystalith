## Context

当前 Crystalith 前端采用固定三栏布局（来源 | 对话 | Studio），面板宽度可拖拽调整但位置固定。Studio 面板内部上方是工具网格（ExtractTo），下方是输出/笔记列表（Notes），两者始终同时可见。

需要迁移到 Modular Canvas 架构，使用 GridStack.js 让用户自由组合工作空间。同时优化 Studio 内部布局——工具区在大多数时候只是"触发入口"，使用频率低于输出列表，应支持收纳以释放空间。

### 选定方案: Modular Canvas (GridStack)

基于 GridStack.js 的模块化自由布局工作区。用户可以像拼积木一样拖拽、缩放任意功能模块，自由组合工作空间。

| 特性 | 说明 |
|------|------|
| GridStack 拖拽引擎 | 12 列网格对齐，碰撞检测自动排列 |
| 模块目录 | 从目录中添加新模块 |
| 锁定/编辑模式 | 编辑完成后锁定布局，防误操作 |
| ⌘K 命令面板 | 所有操作通过命令面板触达 |
| 用户自定义持久化 | 布局可保存/恢复 |

### 已知问题清单 (需在迁移中修复)

1. 图标按钮缺少 `aria-label` (约 10+ 处)
2. 暗色模式 `!important` 覆盖问题
3. `<div onClick>` 应为 `<button>` (约 5 处)
4. 缺少 `autocomplete` 属性
5. 缺少 `touch-action: manipulation`
6. Dialog 缺少 `overscroll-behavior: contain`
7. URL 不反映应用状态

### 设计规范

- **色彩**: 主色调 Amber-600; Light: white/stone-50/stone-100; Dark: stone-950/stone-900/stone-800
- **排版**: DM Sans + Noto Sans SC + 系统字体栈; 正文 11-14px, 行高 1.5-1.6
- **动画**: 150-200ms ease; 必须支持 prefers-reduced-motion; 仅用 transform, opacity
- **无障碍**: aria-label 必须; `<button>` 替代 `<div onClick>`; focus-visible; 键盘可操作

## Goals / Non-Goals

**Goals:**
- 将固定三栏布局替换为 GridStack 模块化自由布局
- 每个功能面板注册为独立 widget（来源、对话、Studio 等）
- Studio 模块内工具区支持折叠/展开
- 提供模块目录（添加/移除 widget）
- 提供 ⌘K 命令面板（快速操作一切）
- 提供锁定/编辑模式切换
- 确保所有 69 项现有功能在新布局下完整可达
- 默认三栏布局合理分配空间比例

**Non-Goals:**
- 不修改后端 API 或数据模型
- 不实现布局持久化/保存到服务端（后续迭代，可先存 localStorage）
- 不改变工具注册和输出插件的架构
- 不重写状态管理层

## Decisions

### 决策 1：Studio 保持单一模块，工具区可收纳

**选择**：Studio 仍为一个 GridStack widget，内部工具区（ExtractTo）支持折叠/展开。

**理由**：
- 工具区和输出列表业务强关联，拆为两个 widget 需要复杂的生命周期联动
- 工具区使用频率低于输出列表——用户大部分时间在浏览输出、编辑笔记
- 收纳设计更简单直接，只是 UI 层的折叠/展开，不涉及 widget 管理
- 折叠后输出列表获得整个 Studio widget 的空间，阅读体验更好

**替代方案**：
- 拆为两个独立 widget + 联动 → 实现复杂，且用户可能困惑两个关联模块的同步行为
- 始终显示工具区 → 浪费空间，输出列表被压缩

### 决策 2：GridStack 与 React 的桥接

**选择**：通过 ReactDOM.createPortal 将 React 组件渲染到 GridStack 管理的 DOM 节点中。

**理由**：GridStack 操作真实 DOM，React 维护虚拟 DOM。使用 portal 可以让 React 组件渲染到 GridStack 创建的容器中，两者互不干扰。

### 决策 3：模块目录交互

**选择**：顶栏"添加模块"按钮打开模块目录弹窗，展示可添加的 widget 列表。

**理由**：简单直接，与命令面板互补——命令面板面向键盘用户，模块目录面向鼠标用户。

### 决策 4：默认布局

**选择**：三栏——来源(w:3) | 对话(w:6) | Studio(w:3)，12 列网格，高度占满可用空间。

**理由**：保持与当前布局的连续性，用户迁移平滑。对话区获得最大空间。

## Risks / Trade-offs

- **[风险] GridStack 包大小**：增加 ~63KB gzipped → 对于桌面应用可接受
- **[风险] React-GridStack 同步**：Portal 渲染时序、widget 增删可能引起短暂闪烁 → 使用 batchUpdate 减少重绘
- **[风险] 工具区收纳后用户找不到**：折叠后工具入口不可见 → 保留明显的展开按钮/提示
- **[权衡] 移动端自由布局意义不大** → 移动端回退为固定堆叠布局（后续处理）
- **[权衡] 锁定模式增加交互步骤** → 默认锁定，编辑时解锁，减少误操作

## Resolved Questions

- **工具区收纳触发方式**：双击标题栏折叠/展开（防误操作，单击不触发）
- **收纳动画**：平滑过渡，200ms ease 高度动画
- **折叠状态持久化**：记住到 localStorage，下次打开保持上次状态
