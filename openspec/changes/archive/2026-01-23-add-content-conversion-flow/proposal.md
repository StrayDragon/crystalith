# 内容转换流程

## Why

用户希望在应用中实现不同内容类型之间的灵活转换，形成知识流动的闭环。当前只支持 Studio 笔记转来源，但用户的对话产出（如问答交互）无法方便地沉淀为可复用的知识来源或结构化笔记。这限制了用户将有价值的对话内容重新利用到后续研究中的能力。

此外，用户反馈 Studio 面板中笔记项的按钮存在交互问题（点不到），需要修复 UI 交互体验。

## What Changes

### 核心功能

1. **对话转 Studio 笔记**
   - 用户可以将单条消息或整个会话导出为 Studio 笔记
   - 支持选择输出类型（段落、要点、结构化等）
   - 保留原始引用信息

2. **对话转来源**
   - 用户可以将单条消息或整个会话转换为来源文档
   - 文档会被分块并嵌入向量存储，可用于后续 RAG 查询
   - 元数据记录来源于对话

3. **转换流程规范**
   - 对话 → Studio 笔记 ✓
   - 对话 → 来源 ✓
   - Studio 笔记 → 来源 ✓（已实现）
   - 来源 → 其他 ✗（来源为最终形态，不可转换）

### UI/UX 改进

4. **修复 Studio 面板笔记项交互**
   - 修复按钮点击区域问题
   - 优化菜单触发交互

5. **添加转换入口**
   - ChatPanel 消息项添加"转换"菜单
   - 支持单条消息转换和会话批量转换

## Impact

- **受影响的规范**：
  - `workspace-ui`: 添加转换 UI 入口和交互
  - `content-conversion`: 新增内容转换功能规范

- **受影响的代码**：
  - 前端：
    - `ChatPanel.tsx` - 添加消息转换菜单
    - `StudioPanel.tsx` - 修复交互问题
    - `useSources.ts` / `useChat.ts` - 添加转换方法
    - `api.ts` / `client.ts` - 添加转换 API 调用
  - 后端：
    - `messages.py` - 添加消息/会话导出端点
    - `outputs.py` - 添加从消息创建输出
    - `sources.py` - 添加从消息/会话创建来源
    - 可能需要新的 `conversions.py` 路由模块

- **数据模型**：
  - 新增转换记录的元数据字段
  - 来源/输出中记录转换来源信息

## 设计约束

1. **单向流动**：转换只能单向进行（对话 → 笔记/来源，笔记 → 来源），不支持逆向
2. **引用保留**：转换时保留原始引用信息，便于追溯
3. **幂等性**：同一内容可多次转换，每次生成新的目标对象
4. **性能考虑**：批量转换时使用后台任务队列

## 相关工作

- 已实现：`convertOutputToSource` API（笔记转来源）
- 相关：`saveContentAsNote` 方法（保存内容到笔记，但不是完整的转换流程）
