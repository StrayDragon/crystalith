# 提案：简化前端 API 客户端使用

## 背景
当前前端在 `frontend/web/src/api/client.ts` 中对 OpenAPI 生成的客户端做了一层封装。该封装：
- 重新导出类型以方便引用。
- 将错误统一包装为自定义 `ApiError`。
- 对部分端点使用手写 `fetch`（例如：来源链接、extractors、SSE QA 流、转换等），因为生成 SDK 尚未覆盖。

虽然使用方便，但这层封装在 API 变化时会引入持续维护成本。用户希望评估是否可以直接使用生成客户端（`frontend/web/src/api/generated/client.gen.ts`），并减少包装层负担。

## 目标
- 通过直接使用生成客户端，降低前端维护成本。
- 仅在生成客户端无法覆盖时保留极小、范围清晰的手写层（如 SSE 流或缺失端点）。
- 保持现有运行时行为与错误提示，除非明确要求变更。

## 非目标
- 不引入后端新功能（除非需要补齐 OpenAPI）。
- 不改变现有 UX/行为流程。
- 不替换生成器或重构构建系统。

## 成功标准
- 前端大多数 API 调用直接使用生成 SDK 的函数。
- 所有手写 `fetch` 调用集中到小模块，并清晰注明原因。
- 错误处理在生成/手写调用间保持一致且可追踪。

## 待确认问题
- 缺失端点是否需要补进 OpenAPI，还是先保留少量手写模块？
- 错误处理是否继续集中到统一的 `ApiError`，还是跟随生成客户端的错误结构？
- 对 SSE/流式端点是否需要形成统一的使用约定？
