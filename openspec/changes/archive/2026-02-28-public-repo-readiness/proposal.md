## Why

- 仓库即将面向公共用户时，“第一次接触”的工程化体验（README/Docs/贡献指南/安全策略/Issue 模板/版本与发布说明）会直接决定用户能否顺利上手与是否愿意贡献。目前仓库仍存在占位信息（如描述字段）、缺少标准社区文件与可发现的支持路径，影响用户友好与维护效率。

## What Changes

- 补齐公共仓库的基础“社区与治理”文件：
  - `SECURITY.md`（漏洞报告方式与响应范围）
  - `CONTRIBUTING.md`（开发/测试/规范/提交流程，必要时指向 docs）
  - Issue/PR 模板与行为准则（按需要选择最小集）
- 修正明显的占位/不一致信息：
  - 后端包元数据（`pyproject.toml` 中 description 等）与仓库 README 的定位一致
  - 文档入口与 Quick Start 的最小闭环可运行
- 明确发布与支持边界：
  - 版本策略（至少说明语义化版本与 tag）
  - 支持矩阵与已知限制（如可选依赖、实验性功能）

## Capabilities

### New Capabilities

- `public-repo-hygiene`: 定义公共仓库的最小工程化与用户友好基线（文档可发现性、贡献路径、安全披露、模板与元数据一致性）。

### Modified Capabilities

- （无）

## Impact

- Repo: 新增/调整根目录治理文件与 `.github/` 下的模板；可能更新部分元数据与 README 文案。
- Docs: 可能需要补充“如何贡献/如何报告问题/如何发布”的可发现入口。
- CI: 预期不改动核心测试链路，但可能增加轻量的文档/链接检查（可选）。
