# Backend（后端）

> TL;DR：Crystalith 的后端服务（Python 3.12+ / FastAPI + async SQLAlchemy + Alembic）。进程入口是 `backend/py/main.py`，应用工厂是 `backend/py/src/crystalith/web/app.py:create_app`（由 `backend/py/src/crystalith/app.py` re-export）。

## Scope（责任边界）

### 做什么
- 提供 `/v1/**` HTTP API（路由集中注册：`backend/py/src/crystalith/web/routers.py:register_routers`）。
- 加载运行时配置（支持 overlay）并在需要时生成配置 JSON Schema（`backend/py/src/crystalith/web/app.py:_load_settings` + `backend/py/src/crystalith/shared/config/manager.py:ConfigManager`）。
- 在启动期（可选）执行数据库迁移（`backend/py/src/crystalith/web/app.py:create_app` 调用 `crystalith.shared.db.migrations.upgrade_head`）。
- 发现/加载插件（entry point group `crystalith.plugins`：`backend/py/src/crystalith/shared/plugins/registry.py:PluginRegistry`）。
- 启动后台任务 worker（`backend/py/src/crystalith/web/app.py:create_app` 启动 `TaskQueue.start_worker()`；队列类型：`backend/py/src/crystalith/features/tasks/queue.py:TaskQueue`）。

### 不做什么
- 不包含前端 UI（见 `frontend/`）。
- 不把环境变量当“业务配置”入口：运行时/业务配置 SSOT 是 `config/app.yaml`（迁移说明：`deployments/_NOTE.md`）。

### 典型使用场景
- 本地只跑后端 API：`cd backend/py && uv sync && just db-init && just dev`（命令入口：`backend/py/justfile`；流程说明：`README.md`）。
- 改 API 后导出/校验 OpenAPI schema：`backend/py/scripts/api_schema.py`（根目录任务：`justfile:api-export` / `justfile:api-check`）。
- 开发/调试官方插件：`backend/py/plugins/*`（约定与安装说明：`backend/py/plugins/README.md`）。

## Module Layout（目录与分层）
- 代码根：`backend/py/src/crystalith/`（布局说明：`backend/py/README.md`）
  - `web/`：FastAPI app 创建、全局依赖、中间件、路由注册（`backend/py/README.md` + `backend/py/src/crystalith/web/app.py:create_app`）
  - `features/`：按业务域切片（路由清单可从 `backend/py/src/crystalith/web/routers.py` 反推）
  - `shared/`：跨域基础设施（config/db/ai/vector_storage/utils；`backend/py/README.md`）
- workspace 包：`backend/py/packages/*`（uv workspace：`backend/py/pyproject.toml:[tool.uv.workspace]`）
- 插件包：`backend/py/plugins/*`（uv workspace：同上；插件约定：`backend/py/plugins/README.md`）
- 分层约束：`web -> features -> shared`，通过 `just check-imports` 校验（`backend/py/README.md` + `backend/py/justfile:check-imports`）。

## Integration（与项目的关系）

### 上游依赖
- 配置文件：`config/app.yaml`（模板语法与关键路径都在文件内注释；加载实现：`backend/py/src/crystalith/shared/config/manager.py`）。
- secrets：`config/secret.env`（示例：`config/secret.env.example`；gitignored：`.gitignore`）。
- 数据目录：默认 `data/`（SQLite/Chroma 默认路径：`config/app.yaml:database.url` 与 `config/app.yaml:vector_storage.chroma.path`；锚定规则说明：`backend/py/README.md`）。

### 下游使用者（已知）
- 前端：`frontend/web` 通过 Vite proxy 调用后端（`frontend/web/vite.config.ts:server.proxy`）。
- 生成物：
  - OpenAPI schema：写入 `frontend/web/openapi.gen.json`（根目录 `justfile:api-export`）。
  - SDK：`sdk/configs/fern/generators.yml` 读取 `frontend/web/openapi.gen.json`，输出到 `vendor/crystalith-sdks/*`（由 `scripts/sdk_gen.sh` 驱动）。

### 关键集成点
- 认证（可选）：`app.auth.enabled` + `app.auth.api_key`（配置：`config/app.yaml:app.auth`；鉴权：`backend/py/src/crystalith/web/auth.py:require_api_key`；配置模型校验：`backend/py/src/crystalith/shared/config/models.py:AppAuthSettings`）。
- 健康检查：`GET /health` 与 `GET /health/dependencies`（实现：`backend/py/src/crystalith/web/app.py:create_app`；compose healthcheck 使用：`deployments/prod/docker-compose.yml`）。
- OpenAPI 与 UI：
  - JSON：`settings.app.openapi_path`（默认：`backend/py/src/crystalith/shared/config/models.py:AppSettings`）
  - UI：`settings.app.openapi_ui_path`，使用 Scalar（`backend/py/src/crystalith/web/app.py:scalar_docs`）。

### 依赖关系图
~~~text
frontend/web (Vite :3000) ──proxy /v1,/health──> backend/py (uvicorn :8032)
   |                                              |
   |                                              +--> config/ (app.yaml + secret.env + schema)
   |                                              +--> data/ (sqlite + chroma + outputs)
   |                                              +--> plugins via entrypoints (backend/py/plugins/*)
   |
   +--> OpenAPI client (openapi.gen.json -> src/api/generated)
           ^                    |
           |                    +-- generated by frontend scripts (frontend/web/package.json)
           |
        exported by backend (backend/py/scripts/api_schema.py, root justfile:api-export)
~~~

## Core Logic（核心概念与核心数据流）

### 术语表
- `Settings`：运行时配置对象（`backend/py/src/crystalith/shared/config/models.py:Settings`）。
- `ConfigManager`：渲染模板（env/secret）→ 解析 YAML → 生成/校验 schema（`backend/py/src/crystalith/shared/config/manager.py:ConfigManager`）。
- Overlay config：`app.local.yaml` / `app.{env}.yaml` / `app.{env}.local.yaml`（发现逻辑：`backend/py/src/crystalith/web/app.py:_discover_overlay_paths`）。
- `PluginRegistry`：扫描 `crystalith.plugins` entry points（`backend/py/src/crystalith/shared/plugins/registry.py:PluginRegistry`）。
- `TaskQueue`：后台任务 worker（`backend/py/src/crystalith/features/tasks/queue.py:TaskQueue`）。
- `StageLimiters`：并发限流（`backend/py/src/crystalith/shared/concurrency/limiters.py:StageLimiters`）。

### 主流程（启动 → 提供 API）
1. 进程入口：`backend/py/main.py:main` 读取 `HOST/PORT/RELOAD`，调用 `uvicorn.run("crystalith.app:create_app", factory=True, ...)`。
2. 配置加载：`backend/py/src/crystalith/web/app.py:_load_settings`
   - 定位 `config/app.yaml`：优先 `CRYSTALITH_CONFIG_PATH`/`CRYSTALITH_CONFIG_DIR`（env SSOT：`backend/py/src/crystalith/shared/env.py`），否则向上查找（`_find_config_path`）。
   - 发现 overlay：由 `CRYSTALITH_ENV` 影响（`_discover_overlay_paths`）。
   - schema 缺失时自动写入：`ConfigManager.write_schema()`（触发点在 `_load_settings`）。
3. 依赖装配：`backend/py/src/crystalith/web/app.py:create_app`
   - DB / Vector store / Cache provider / Limiters / Plugins / Queue 都在此装配并挂到 `app.state.*`。
4. 生命周期（lifespan）：
   - `app.startup.auto_db_init=true` 时迁移：`upgrade_head`（`backend/py/src/crystalith/web/app.py:create_app` lifespan）。
   - 插件加载：`app.state.plugins.load_from_entry_points(...)`（entry point group 常量：`backend/py/src/crystalith/shared/plugins/registry.py:PluginRegistry.entrypoint_group`）。
   - 启动 worker：`app.state.task_queue.start_worker()`；关闭时释放资源（DB/vector/cache/openai clients）。
5. 路由与错误处理：
   - 路由注册：`backend/py/src/crystalith/web/routers.py:register_routers`
   - 统一错误响应：exception handlers 注册在 `backend/py/src/crystalith/web/app.py:create_app`。

### 重要边界条件
- 模板渲染优先级：模板读取 `os.environ` 并被 `.env` 覆盖（`backend/py/src/crystalith/shared/config/manager.py:ConfigManager._template_context`）。
- `app.auth.enabled=true` 但未配置 `api_key` 会导致启动后请求 500（`backend/py/src/crystalith/web/auth.py:require_api_key` + `backend/py/src/crystalith/shared/config/models.py:AppAuthSettings`）。
- optional services 探测：`/health/dependencies` 在需要时刷新探测（`backend/py/src/crystalith/web/app.py:dependency_health`），后台 monitor 由 `CRYSTALITH_OPTIONAL_SERVICES_MONITOR_*` 控制（env SSOT：`backend/py/src/crystalith/shared/env.py`）。

## Dev / Run / Test（开发者使用指南）
```bash
# 后端依赖安装（uv workspace）
cd backend/py
uv sync                           # 依据：backend/py/AGENTS.md

# 本地运行（无 Docker）
just db-init                       # 依据：backend/py/README.md + backend/py/justfile
just dev                           # 依据：backend/py/justfile

# 质量门 / 测试
just check                         # 依据：backend/py/justfile
just test                          # 依据：backend/py/justfile
```

```bash
# repo root：统一启动（profiles：local|hybrid|docker|full）
just up                            # 依据：justfile:up + scripts/orchestrate.sh
```

```bash
# repo root：OpenAPI schema
just api-export                     # 依据：justfile:api-export
just api-check                      # 依据：justfile:api-check
```

## Config / Observability（配置与可观测性）
- 关键 env var（后端运行时）：
  - 配置定位：`CRYSTALITH_CONFIG_PATH` / `CRYSTALITH_CONFIG_DIR`（`backend/py/src/crystalith/shared/env.py`）
  - 数据目录覆盖：`CRYSTALITH_DATA_DIR`（同上）
  - optional services 探测：`CRYSTALITH_OPTIONAL_SERVICES_MONITOR_*`（同上）
- 关键运行时配置路径（`config/app.yaml`）
  - `app.auth.*`、`app.cors.*`、`app.startup.*`（对应模型：`backend/py/src/crystalith/shared/config/models.py:AppSettings`）
  - `database.*`、`vector_storage.*`、`cache.*`（同上）
- 日志（开发默认）：
  - Procfile 默认注入 `LOG_LEVEL=DEBUG LOGX_FORMAT=console`（`Procfile`）
  - 依赖 `lush-logx`（通过 PyPI 安装，声明：`backend/py/pyproject.toml:dependencies`）。

## Roadmap（未来方向与优化建议）
- 近期（1–2 周）
  - 补齐“配置 overlay + data 目录锚定”的统一文档入口（动机：减少路径/环境漂移；收益：更快定位问题；风险：需同步 docs；方案：基于 `backend/py/README.md`、`backend/py/src/crystalith/web/app.py:_discover_overlay_paths`、`config/app.yaml` 更新 docs）。
  - 为核心路由补更细粒度契约测试与错误码断言（动机：防止 API 行为漂移；收益：更稳的前端/SDK 生成链路；风险：维护成本；方案：从 `backend/py/src/crystalith/web/routers.py` 的路由清单挑选核心路径扩展 `backend/py/tests/contract/`）。
- 中期（1–2 月）
  - 插件加载报告可视化/可查询（动机：排障；收益：明确哪些插件被跳过及原因；风险：需注意信息暴露；方案：复用 `backend/py/src/crystalith/shared/plugins/registry.py:PluginLoadReport` 增加只读端点）。
  - 统一 optional service 的“降级提示”与“恢复动作”文案（动机：减少黑盒错误；收益：更好 UX；风险：需要前后端联动；方案：从 `backend/py/src/crystalith/web/app.py:_optional_recovery_hint` 出发做标准化）。
- 长期（季度+）
  - 任务处理从“同进程 worker”演进为可独立扩容的 worker 进程（动机：吞吐/隔离；收益：资源更可控；风险：部署复杂；方案：保持 `TaskQueue` 接口，增加独立入口与部署 overlay）。
  - 强化观测：结构化日志字段、SSE 时延/阶段耗时（动机：生产排障；收益：定位瓶颈更快；风险：需要规范；方案：沿用 `CRYSTALITH_OBSERVABILITY_SSE_TIMINGS`（`backend/py/src/crystalith/shared/env.py`）与现有日志框架扩展）。
